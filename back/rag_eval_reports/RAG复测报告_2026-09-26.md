# RAG 续费后复测报告（2026-09-26）

## 测试方式

沿用首次评测的独立 MySQL 测试库、Chroma 集合和论坛文章 7–11。使用 `qwen3.7-text-embedding`、`qwen3.7-max`、Elasticsearch BM25、向量检索与项目现有 RRF 逻辑，对 [`rag_eval_cases.json`](../testdata/rag_eval_cases.json) 中 35 道题执行完整问答：30 道有答案题、5 道应拒答题。`topK=5`，父子分块开启，重排关闭。密钥仅在评测进程中注入，未写入文件。

## 拒答题核对

| 问题类型 | 实际表现 |
| --- | --- |
| 今天美元兑人民币实时汇率 | 明确说文章无法确定实时汇率；没有编造汇率 |
| 美联储下周利率 | 明确说无法确定；没有预测数值 |
| 当前最值得买入的股票 | 明确说无法确定；没有推荐个股 |
| USDC 今天市值 | 说明文章只提到 USDC，没有实时市值 |
| 明天黄金现货价格 | 明确说无法确定；没有预测价格 |

**展示问题：**5 条拒答回答都带有文章编号，其中前 2 条的“参考来源”由 `normalizeRAGCitations` 自动追加。文章只说明相关背景，并不能支持被问的实时数值或预测。建议拒答时不要自动附上全部召回文章，或明确标注它们只是“检索到的相关背景”。

## 结果边界与部署状态

- 这套题只覆盖 5 篇文章，且大多数问题围绕单篇文章编写。100% 的 Hit@3 和拒答率只适用于当前小语料和本次运行，不应直接作为大规模论坛效果承诺。30/30 的引用正确率也没有逐句验证答案事实。
- 本轮没有做并发压测；上述延迟不能解释为 QPS。实际 API 账单费用未从提供方读取，原始 JSON 中的 `estimated_total_cost_cny=0` 仅表示没有配置估价参数。
- 此次评测仍运行于独立测试库和独立 Chroma 集合。复查发现，运行中的 `forum-back` 容器仍未设置 `RAG_DASHSCOPE_KEY` 环境变量，原论坛文章 7–11 的 `rag_status` 仍为 `failed`。续费解决了评测进程的模型调用问题，并没有自动让已部署的 `/api/rag/ask` 恢复。
